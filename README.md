## 设计要点

**主循环**：`while (should_run)` 不停显示 `osh>` 提示符，`fgets` 读最多 79 字符的命令行，输入 `exit` 或按 Ctrl+D 退出。每轮循环开头先用 `waitpid(-1, NULL, WNOHANG)` 扫一遍，把跑完的后台子进程回收掉，不留僵尸。

**进程控制（Part I）**：`strtok` 把命令行按空格切成 `args[]`（NULL 结尾），`fork()` 复制出子进程，子进程用 `execvp(args[0], args)` 变身成目标程序（失败就报错退出，绝不能让它继续跑 shell 循环）。命令末尾带 `&` 时（`ls &` 和 `ls&` 两种写法都认），父进程不等待、父子并发；否则父进程 `waitpid(pid, ...)` 点名等这个孩子，避免把后台孩子的退出状态错收走。

**历史功能（Part II）**：10 个格子的循环缓冲区，第 N 条命令放 `(N-1)%10` 号格子，编号从 1 连续递增，超 10 条自动顶掉最旧的。

- `history`：从新到旧列出保留的命令（`编号 命令`），编号跨过 10 继续往上数（敲了 12 条就显示 3\~12）；history 自身不入史
- `!!`：重跑上一条；`!N`：重跑编号 N 的那条，N 必须还在最近 10 条的窗口里
- 由 `!!`/`!N` 执行的命令先回显，再作为新命令入史（连敲两次 `!!` 历史里就有两条一样的）
- 空历史敲 `!!` 报 `No commands in history.`；编号查不到报 `No such command in history.`

**踩过的坑**：记历史必须放在 `strtok` 之前——strtok 会把空格改成 `\0`，先切再存的话 `ls -l` 进历史就只剩 `ls`；history 打印和 `!N` 查询不能默认"格子 i-1 住着第 i 条命令"，转一圈覆盖后编号会错位，要先算窗口下限 `oldest`。这两个坑都是在测试里实际撞上的，修复过程见 git 提交记录。

## 编译方法

在 Linux（或 WSL、macOS）下：

```bash
make            # 等价于: gcc -Wall -Wextra -O2 -std=gnu11 -o osh shell.c
make clean      # 删掉编译产物 osh
```

## 使用方法

```bash
./osh
```

示例会话：

```
osh> date
osh> ls -l
osh> history
2 ls -l
1 date
osh> !!          # 重跑 ls -l（先回显命令）
osh> !2          # 重跑 2 号命令
osh> sleep 30 &  # 后台运行，父子进程并发
osh> ps          # 前台运行，父进程等子进程
osh> exit
```
